# Azure Server Fleet Management & Observability

## 1. Network Overview

The network design provides private connectivity for the Windows and Linux workload VMs and a controlled administrative access path through Azure Bastion.

The development environment is deployed in Canada Central. Workload VMs do not receive public IP addresses.

## 2. Virtual Network

| Property | Value |
|---|---|
| Region | Canada Central |
| Address space | `10.10.0.0/16` |
| Name | Generated from project, environment, region code, and random suffix |

The VNet is created by the networking module. Its name is exposed through a module output for use by the Bastion module.

## 3. Subnet Design

The VNet contains a workload subnet and a dedicated Bastion subnet.

| Subnet | Name | Address prefix | Purpose |
|---|---|---|---|
| Workload | Generated by Terraform | `10.10.0.0/24` | Hosts the Windows and Linux VMs |
| Bastion | `AzureBastionSubnet` | `10.10.1.0/26` | Hosts Azure Bastion |

The Bastion subnet is created by the Bastion module and uses the required subnet name `AzureBastionSubnet`.

## 4. Network Security Group

A Network Security Group is associated with the workload subnet.

The submitted networking module defines these inbound rules:

| Rule | Protocol | Destination port | Source |
|---|---|---:|---|
| `allow-bastion-rdp` | TCP | 3389 | `10.10.1.0/26` |
| `allow-bastion-ssh` | TCP | 22 | `10.10.1.0/26` |

These rules permit the Bastion subnet to reach the Windows RDP and Linux SSH management ports on the workload subnet.

This table documents the explicit rules defined in the submitted module; it is not a complete inventory of Azure's default NSG rules or any rules configured outside this module.

## 5. Azure Bastion

Azure Bastion is deployed with the Basic SKU.

The Bastion module provisions:

- A dedicated public IP address.
- The `AzureBastionSubnet`.
- An Azure Bastion host.
- An IP configuration associating the Bastion host with its public IP and subnet.

The Bastion module receives the VNet name from the networking module output. The Bastion public IP is assigned to the Bastion service, not to the workload VMs.

## 6. Virtual Machine Network Placement

Both workload VMs are connected to the workload subnet through network interfaces with dynamically allocated private IP addresses.

| Workload | Operating system | Network placement | Public IP |
|---|---|---|---|
| Windows VM | Windows Server 2022 Datacenter | Workload subnet | None assigned by the submitted VM module |
| Linux VM | Ubuntu Server 22.04 LTS | Workload subnet | None assigned by the submitted VM module |

## 8. Network Security Principles

The implemented network design follows these principles:

- Workload VMs do not receive public IP addresses.
- Administrative connectivity is provided through Azure Bastion.
- RDP and SSH inbound rules are sourced from the Bastion subnet.
- The NSG is associated with the workload subnet.
- The Bastion public IP is separate from the private VM network interfaces.

Further NSG hardening, outbound traffic restrictions, and network security monitoring should be assessed as separate work items rather than assumed to be implemented.
